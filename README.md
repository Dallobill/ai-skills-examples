# AI Skills Examples

A public, sanitized portfolio of reusable AI operating skills.

This repository demonstrates how I structure AI-assisted workflows as repeatable systems instead of one-off prompts. The examples are adapted from real operating patterns I use across program management, basketball operations, software development, GitHub workflows, and daily learning.

> **Privacy note:** This is a showcase repository. Names, organizations, source-system URLs, schedules, prices, client/player records, internal policies, and other private operational details have been removed or replaced with fictional examples.

## What this demonstrates

- source-of-truth-first agent design
- reusable `SKILL.md` operating procedures
- clear workflow state machines
- separation of planning vs. completed work
- human-in-the-loop operational controls
- connected-tool execution patterns
- validation and no-fabrication rules
- privacy-aware public/private repository architecture
- Issue → Branch → PR → Review → Merge development workflow

## Example skills

| Skill | Purpose |
| --- | --- |
| `youth-program-operations` | Turn a curriculum, schedule, staff rotation, and delivery log into weekly staff-ready operations. |
| `basketball-business-operations` | Manage leads, athletes, evaluations, packages, scheduling, payments, and retention without mixing business contexts. |
| `coding-development` | Make code changes from repository context with minimal, validated implementation. |
| `github-development-workflow` | Execute disciplined Issue → Branch → PR development workflows. |
| `30-minute-learning-block` | Run compact learning sessions using retrieval, explanation, practice, and recall. |

## Design model

```text
Live source / repository / connected system
                ↓
             AI skill
                ↓
       operating rules + state
                ↓
        action / artifact / update
                ↓
             validation
                ↓
         next system state
```

A skill is not just a prompt. It defines **how the agent should work**: what sources to read, what rules to preserve, what it may update, what it must never invent, and how to verify completion.

## Public vs. private architecture

My production skills live separately from this showcase repository. The private layer can reference real connected systems and operational details. This public repository contains only sanitized patterns and fictional examples suitable for portfolio review.

## Status

This repository is intentionally example-driven. The skill structures evolve as the underlying workflows are tested in real use.
